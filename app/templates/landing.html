How SpecDrift Works

SpecDrift analyzes your Swagger 2.0 and OpenAPI 3.0 specifications to identify changes between versions. Our intelligent comparison engine categorizes every difference by its impact on API consumers.

Detection Capabilities

Endpoint Changes

  • Added, removed, or modified API paths
  • HTTP method changes (GET, POST, PUT, DELETE, etc.)
  • Operation summary and description updates

Parameter Changes

  • Required vs. optional parameter modifications
  • Parameter type, format, and validation rule changes
  • Query, path, header, and body parameter differences
  • Default value modifications

Request & Response Changes

  • Request body schema modifications
  • Response status code changes
  • Response schema structure differences
  • Content-Type and media type changes

Schema & Model Changes

  • Property additions, removals, and type changes
  • Required vs. optional property modifications
  • Enum value changes
  • Array item and object property changes

Security & Authentication

  • Authentication scheme changes
  • Security requirement modifications
  • OAuth scope changes

Frequently Asked Questions

What is API contract drift?

API contract drift occurs when an API specification changes in ways that break client expectations. This happens when endpoints are removed, required parameters are added, or response structures change unexpectedly. SpecDrift detects these drifts automatically.

What's the difference between breaking and non-breaking changes?

Breaking changes force clients to update their code immediately (e.g., removing an endpoint, adding a required field). Potentially breaking changes might cause issues depending on implementation (e.g., changing response status codes). Non-breaking changes are safe—like adding optional fields or new endpoints.

How do I use SpecDrift?

Upload or paste two Swagger / OpenAPI specifications, click "Compare Specs," and SpecDrift instantly shows all changes categorized by risk level.

What file formats does SpecDrift support?

SpecDrift accepts Swagger 2.0 and OpenAPI 3.0, and compatible formats in JSON or YAML. You can paste specs directly or upload files. You can even compare a Swagger 2.0 specification to an OpenAPI 3.0 specification.

Is my data private and secure?

Yes. SpecDrift processes comparisons on-the-fly without storing your specifications. No signup, no tracking. Your data stays with you.

Why should I use SpecDrift instead of manual review?

Manual review is error-prone and slow, especially with large or complex APIs. SpecDrift automatically flags issues in seconds, catches edge cases

Can I use SpecDrift in my CI/CD pipeline? In Development

SpecDrift's API endpoint accepts spec comparisons programmatically, making it ideal for automated API validation during deployments.

What happens when endpoints or fields are removed?

SpecDrift flags removed endpoints and required fields as breaking changes. Clients depending on these will fail unless they update.

Does SpecDrift work with both JSON and YAML?

Yes! SpecDrift supports both JSON and YAML formats for Swagger 2.0 and OpenAPI 3.0 specifications. You can even compare a JSON spec against a YAML spec—the format doesn't matter.

How accurate is SpecDrift's analysis?

SpecDrift uses comprehensive rule-based analysis specifically designed for OpenAPI specifications. It understands API semantics, not just text differences, ensuring accurate categorization of changes by their actual impact on API consumers.

Can I compare specifications from different API versions?

Absolutely. SpecDrift is designed to compare any two OpenAPI specifications, whether they're different versions of the same API, alternative designs, or completely different APIs. The tool works best when comparing versions of the same API.

What should I do if I find breaking changes?

Consider these options: (1) Revert the breaking changes, (2) Create a new major version of your API, (3) Provide a migration path and deprecation timeline, (4) Add backward-compatible alternatives alongside the new implementation.

Getting Started with SpecDrift

Ready to compare your API specifications? Follow these simple steps:

  1. Prepare your two API specifications (old version and new version) in Swagger 2.0 or OpenAPI 3.0 format
  2. Visit the comparison page and either upload your files or paste the content directly
  3. Click "Compare Specs" to run the analysis
  4. Review the categorized results: breaking changes, potentially breaking changes, and non-breaking changes
  5. Take appropriate action based on the findings—update documentation, notify API consumers, or adjust your implementation
